The assimilation cycle

The analysis chapters take one forecast ensemble to one analysis ensemble. Real assimilation is a cycle of forecast, analysis and inflation over a stream of observations Evensen, 2009Carrassi et al., 2018Asch et al., 2016. Filterax keeps the mathematics apart from the loop, so one analysis step can serve a Python loop, a compiled scan or an external orchestrator.

Three things organise this chapter. The filtering recursion says what the loop must compute, and for a linear model it has an exact answer to test against. The protocols and result types are the contract between the layers. And the same step can be driven by several loops, which differ in what they retain and what they drop.

The filtering recursion¶

Filtering alternates a prediction, which carries the posterior through the dynamics, with an update, which applies Bayes’ rule to one window:

p(xt∣y1:t−1)=∫p(xt∣xt−1)p(xt−1∣y1:t−1)dxt−1,p(\vect{x}_t \mid \vect{y}_{1:t-1}) = \int p(\vect{x}_t \mid \vect{x}_{t-1}) p(\vect{x}_{t-1} \mid \vect{y}_{1:t-1}) \mathrm{d} \vect{x}_{t-1},p(xt​∣y1:t−1​)=∫p(xt​∣xt−1​)p(xt−1​∣y1:t−1​)dxt−1​,
(16.1)
p(xt∣y1:t)=p(yt∣xt)p(xt∣y1:t−1)p(yt∣y1:t−1).p(\vect{x}_t \mid \vect{y}_{1:t}) = \frac{p(\vect{y}_t \mid \vect{x}_t) p(\vect{x}_t \mid \vect{y}_{1:t-1})}{p(\vect{y}_t \mid \vect{y}_{1:t-1})}.p(xt​∣y1:t​)=p(yt​∣y1:t−1​)p(yt​∣xt​)p(xt​∣y1:t−1​)​.
(16.2)

The denominators accumulate into the evidence, which is the quantity diagnostics (chapter 13) and training (chapter 14) rely on:

log⁡p(y1:T)=∑t=1Tlog⁡p(yt∣y1:t−1).\log p(\vect{y}_{1:T}) = \sum_{t=1}^{T} \log p(\vect{y}_t \mid \vect{y}_{1:t-1}).logp(y1:T​)=t=1∑T​logp(yt​∣y1:t−1​).
(16.3)

The ensemble form runs each window with a time stamp τt\tau_tτt​, and τ0\tau_0τ0​ is the t0 argument. Each member moves from τt−1\tau_{t-1}τt−1​ to τt\tau_tτt​ through fff, the analysis produces Xt∣t⋆\mat{X}^\star_{t \mid t}Xt∣t⋆​, and the optional inflator acts on it with the forecast available:

Xt∣t−1=f(Xt−1∣t−1;τt−1,τt),Xt∣t⋆=analysis(Xt∣t−1,yt),Xt∣t=inflate(Xt∣t⋆,Xt∣t−1).\mat{X}_{t \mid t-1} = f(\mat{X}_{t-1 \mid t-1}; \tau_{t-1}, \tau_t), \qquad \mat{X}^\star_{t \mid t} = \op{analysis}(\mat{X}_{t \mid t-1}, \vect{y}_t), \qquad \mat{X}_{t \mid t} = \op{inflate}(\mat{X}^\star_{t \mid t}, \mat{X}_{t \mid t-1}).Xt∣t−1​=f(Xt−1∣t−1​;τt−1​,τt​),Xt∣t⋆​=analysis(Xt∣t−1​,yt​),Xt∣t​=inflate(Xt∣t⋆​,Xt∣t−1​).
(16.4)

All three ensembles are NE×DxN_\mathcal{E} \times D_xNE​×Dx​, fff applies member by member, and τt\tau_tτt​ is a scalar. The factor in (16.3) is approximated at window ttt by log⁡N(rˉt;0,Σ^y,t)\log \mathcal{N}(\bar{\vect{r}}_t; \vect{0}, \hat{\gmat{\Sigma}}_{y,t})logN(rˉt​;0,Σ^y,t​), computed from the forecast and so before inflation of that window. Two restrictions come with the loop. The forecast has no ηt\gvect{\eta}_tηt​ of its own, so model error enters only if fff samples it or an inflator stands in for it. And Σε\gmat{\Sigma}_\varepsilonΣε​ is fixed for the whole call, which also fixes DyD_yDy​.

The linear case¶

Take f(x)=Fxf(\vect{x}) = \mat{F} \vect{x}f(x)=Fx and h(x)=Hxh(\vect{x}) = \mat{H} \vect{x}h(x)=Hx, with no inflation. A square-root filter (chapter 6) then keeps the sample mean and covariance exactly on the Kalman recursion, started from the initial sample moments:

μx,t∣t−1=Fμx,t−1∣t−1,Σx,t∣t−1=FΣx,t−1∣t−1F⊤,\gvect{\mu}_{x,t \mid t-1} = \mat{F} \gvect{\mu}_{x,t-1 \mid t-1}, \qquad \gmat{\Sigma}_{x,t \mid t-1} = \mat{F} \gmat{\Sigma}_{x,t-1 \mid t-1} \mat{F}^\top,μx,t∣t−1​=Fμx,t−1∣t−1​,Σx,t∣t−1​=FΣx,t−1∣t−1​F⊤,
(16.5)
μx,t∣t=μx,t∣t−1+Gtrt,Σx,t∣t=Σx,t∣t−1−GtHΣx,t∣t−1,\gvect{\mu}_{x,t \mid t} = \gvect{\mu}_{x,t \mid t-1} + \mat{G}_t \vect{r}_t, \qquad \gmat{\Sigma}_{x,t \mid t} = \gmat{\Sigma}_{x,t \mid t-1} - \mat{G}_t \mat{H} \gmat{\Sigma}_{x,t \mid t-1},μx,t∣t​=μx,t∣t−1​+Gt​rt​,Σx,t∣t​=Σx,t∣t−1​−Gt​HΣx,t∣t−1​,
(16.6)

with rt=yt−Hμx,t∣t−1\vect{r}_t = \vect{y}_t - \mat{H} \gvect{\mu}_{x,t \mid t-1}rt​=yt​−Hμx,t∣t−1​, Σy,t=HΣx,t∣t−1H⊤+Σε\gmat{\Sigma}_{y,t} = \mat{H} \gmat{\Sigma}_{x,t \mid t-1} \mat{H}^\top + \gmat{\Sigma}_\varepsilonΣy,t​=HΣx,t∣t−1​H⊤+Σε​ and Gt=Σx,t∣t−1H⊤Σy,t−1\mat{G}_t = \gmat{\Sigma}_{x,t \mid t-1} \mat{H}^\top \gmat{\Sigma}_{y,t}^{-1}Gt​=Σx,t∣t−1​H⊤Σy,t−1​. Linear prediction moves the sample moments exactly, because a linear map of an ensemble has the mapped mean and covariance. Chapter 6 shows the analysis does the same. So no sampling error appears at any window once the initial ensemble is given, and this is an exact test of a whole cycle.

Implementation in filterax¶

Layer 1: the analysis¶

A Layer 1 filter is a stateless AbstractSequentialFilter, with one method taking a forecast ensemble, an observation, an observation operator and a noise covariance. It owns no time, no dynamics and no state, and it returns an AnalysisResult:

FieldShapeMeaning
particlesNE×DxN_\mathcal{E} \times D_xNE​×Dx​the analysis ensemble
log_likelihoodscalar, or Nonelog⁡N(rˉ;0,Σ^y)\log \mathcal{N}(\bar{\vect{r}}; \vect{0}, \hat{\gmat{\Sigma}}_y)logN(rˉ;0,Σ^y​)
diagnosticsdict, or Noneoptional extras from the filter

Layer 1 lives in filterax.filters: ETKF, ETKF_Livings, EnSRF, EnSRF_Serial, ESTKF, LETKF and StochasticEnKF.

Layer 2: the loop¶

The Layer 2 models in the top-level namespace are flx.ETKF, flx.EnSRF, flx.StochasticEnKF, flx.LETKF, and the latent wrappers of chapter 15. Sharing a name does not make them Layer 1 classes. flx.ETKF has dynamics, obs_op and inflator fields and an assimilate method, and it is not an AbstractSequentialFilter. assimilate takes a sequence of (y, t) pairs and runs (16.4) in a plain Python for loop, which is easy to replace. It returns an AssimilationResult:

FieldShapeMeaning
particlesNE×DxN_\mathcal{E} \times D_xNE​×Dx​the terminal ensemble, ready for a follow-up forecast
forecast_historyT×NE×DxT \times N_\mathcal{E} \times D_xT×NE​×Dx​Xt∣t−1\mat{X}_{t \mid t-1}Xt∣t−1​ at each window
analysis_historyT×NE×DxT \times N_\mathcal{E} \times D_xT×NE​×Dx​Xt∣t\mat{X}_{t \mid t}Xt∣t​ at each window, after inflation
log_likelihoodsTTT, or Nonethe factors of (16.3), one per window

A missing likelihood at one window is padded with NaN so the time axes stay aligned. Every shipped filter reports one, so no shipped model reaches that path. With no windows, the histories have a leading axis of length 0 and log_likelihoods is None.

The example is a linear model of two damped rotations, with NE=8N_\mathcal{E} = 8NE​=8 members and Dx=4D_x = 4Dx​=4. Components 0 and 2 are observed at noise variance 0.1 over T=10T = 10T=10 windows. It implements three protocols as small modules.

It prints (8, 4) (10, 8, 4), then (10, 8, 4) (10,), then -5.497, then (0, 8, 4) None.

The protocols¶

Every extension point is an abstract equinox.Module, so an implementation is a PyTree that survives jit, grad and vmap. They do not all have a consumer yet, which is worth knowing before implementing one.

ProtocolMethodConsumed byShips with

The dynamics are called on one member, so the loops wrap them in a vmap over members with the two times held fixed. A plain function with the right signature also works in Layer 2, as chapter 6 shows, since the fields are not checked at run time.

AbstractNoise bundles a covariance and a sampler, and the filters take the operator alone, so pass noise_model.covariance() as in Program 16.1. AbstractLocalizer has no consumer because LETKF takes a radius and the other localized routes take taper arrays (chapter 11). A subclass is useful in your own loop, built on the primitives as in Program 16.3.

Inflators in the loop¶

An inflator runs after the analysis and before the next forecast, and it receives both ensembles so that relaxation methods can reach the forecast. The derivations are in chapter 12, and all of these preserve the analysis mean.

MultiplicativeInflator Anderson & Anderson, 1999X~←ζX~\tilde{\mat{X}} \leftarrow \zeta \tilde{\mat{X}}X~←ζX~factor, ζ\zetaζ

RTPP Zhang et al., 2004X~←(1−α)X~+αX~t∣t−1\tilde{\mat{X}} \leftarrow (1 - \alpha) \tilde{\mat{X}} + \alpha \tilde{\mat{X}}_{t \mid t-1}X~←(1−α)X~+αX~t∣t−1​alpha, α\alphaα
AdditiveInflator Hamill & Whitaker, 2005adds a mean-free draw from a given covariancenoise_cov, base_key

Three details of the loop matter. The stored analysis_history holds the inflated ensemble. The likelihood at window ttt comes from the forecast, so inflation at window ttt first affects the likelihood at window t+1t + 1t+1. And the Layer 2 loop passes step= to the inflator, which AdditiveInflator folds into its key for a fresh draw at each window. Called with no step, it repeats one draw.

It prints 0.0000 -0.0445, then 0e+00, then 0.218, then 0.000. So inflation leaves the first likelihood alone and changes the second, and the first stored analysis is exactly the inflated one. Only a changing step gives a new draw.

Program 16.5 returns to the diverging run of chapter 6. That is Lorenz-96 with Dx=40D_x = 40Dx​=40, half the sites observed with unit variance, and only NE=20N_\mathcal{E} = 20NE​=20 members, over 200 windows. It uses differentiable_assimilate for speed, since Program 16.6 shows it matches the Python loop. That function refuses AdditiveInflator, so the last case is a scan over FilterState that passes step= as the Layer 2 loop does.

These are single settings on one toy, so they are not a ranking of the methods. They do show the shape of the trade-off. Without inflation the error is nine times the spread, and modest multiplicative inflation or RTPS brings it well below the observation noise with a matching spread. More is not better. A factor of 1.2 costs accuracy, and RTPS(0.9) makes the ensemble blow up with no exception raised, so the run ends in nan. Check that a history is finite before reading its statistics.

Cycling through pipekit¶

pipekit-cycle orchestrates assimilation cycles for any algorithm library through three runtime-checkable protocols. Conformance is structural: filterax never imports pipekit, and the adapters in filterax.pipekit lift filterax components to the right shapes.

pipekit protocolContractfilterax adapterWhat the adapter does
AnalysisStep__call__(forecast, obs, *, obs_op, obs_err_cov)FilterAnalysisStep(filter, analysis_kwargs)stacks a list of members and returns the same kind of container, coerces a dense obs_err_cov to a tagged operator, and raises ValueError if it is missing
ForwardModelstep(state, dt), dt, state_signatureDynamicsForwardModel(dynamics, dt)integrates over [0,dt][0, \mathrm{d}t][0,dt]
ObservationOperator__call__(state), linearize(state)LinearizableObsOperator(obs_op)derives the Jacobian with jax.jacfwd

EnsembleDACycle holds the ensemble as a Python list of member states. It draws each observation from an obs_source, a pipekit Operator called with the cycle index. Σε\gmat{\Sigma}_\varepsilonΣε​ travels on the DAState, and is a dense array or a lineax operator. Program 16.6 runs the toy model of this chapter through it, for real.

It prints True True True, then list 8 10 10.0, then 6e-16, 2e-15, 0e+00 and 1e-15, then six times True. The container comes back as the list it went in as, and DAState has counted 10 cycles and advanced its clock. All three loops agree to round-off, and the derived Jacobian equals H\mat{H}H. pipekit owns the loop, the scheduling and the state container, and filterax owns the ensemble mathematics inside FilterAnalysisStep. Swapping ETKF for another filter changes nothing else, and LETKF passes its coordinates through analysis_kwargs.

The other filterax types also fit pipekit-cycle’s wider protocols structurally, though EnsembleDACycle has no slot for them. That is why inflation needs the small InflatedStep wrapper above, whose result matches the Layer 2 run with the same RTPP. The loop also drops things that Layer 2 keeps, as follows.

  • FilterAnalysisStep returns only the ensemble, so log_likelihood and diagnostics are discarded.

  • obs_source receives an index that restarts at 0 on every call of the cycle, so resuming a run needs an offset of your own.

  • DynamicsForwardModel integrates over [0,dt][0, \mathrm{d}t][0,dt] on every cycle, because pipekit does not pass absolute time, so the dynamics must be autonomous.

  • pipekit passes no PRNG key to the analysis, so a stochastic filter reuses its stored key and repeats its perturbations, where Layer 2 flx.StochasticEnKF folds in a new key per window.

Program 16.7 measures the last two.

It prints [1. 4. 9.], then [1.0, 2.0, 3.0], then 0.0. The Layer 2 forecast follows the time-dependent forcing from τt−1\tau_{t-1}τt−1​ to τt\tau_tτt​, while the adapter applies the first interval three times. Two calls of the stochastic step give identical perturbations.

When it breaks¶

The loop adds few failure modes of its own, and most of what can go wrong here fails silently.

  • With no model noise and no inflation, the spread collapses and the observations stop mattering, as the first row after Program 16.5 shows.

  • Too much inflation gives nan and no exception, as its RTPS(0.9) row shows.

  • Setting inflator or localizer on a FilterConfig has no effect, as Program 16.3 shows, so set inflator on the model.

  • An observation network that changes between windows does not fit assimilate or differentiable_assimilate, which each take one Σε\gmat{\Sigma}_\varepsilonΣε​ per call, so write your own loop around filter.analysis.

  • Time-dependent dynamics and stochastic filters both lose something through the pipekit adapters, as Program 16.7 shows.

When each loop is the right answer¶

All of these call the same Layer 1 analysis, so they agree where they overlap.
